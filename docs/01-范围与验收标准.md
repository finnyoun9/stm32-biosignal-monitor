# 范围与验收标准

> 这份文档回答面试里最容易被追问的两个问题：**「你到底做了多少」**和**「怎么证明它是对的」**。
> 原则：每个阶段都有**可复现的验收证据**；没有证据的部分不进简历。

## 一、范围（做什么 / 不做什么）

**做**
- 端侧生理信号**采集链路**：传感器驱动 → 时序与缓冲 → 质量判断 → 上报
- **信号处理**：PPG 心率/HRV、SpO2 的 ratio-of-ratios 方法、ECG 的 QRS 检测
- **低功耗**：采样占空比、MCU 低功耗模式与唤醒、连续运行稳定性
- **可验证性**：串口协议带长度与 CRC、丢包统计、上位机回放与绘图

**不做**
- 不做医疗诊断、不下医学结论
- 不声称 SpO2 数值准确（没有参考血氧仪做标定，只做方法验证）
- 不做算法创新（用公开论文与参考设计的成熟方法）
- 不做无线/云平台（BLE 上报只作为可选扩展，不是本项目主线）

## 二、阶段与验收标准

### P0 算法原型（无需硬件）——本轮交付

| 验收项 | 标准 | 证据 |
|---|---|---|
| 合成信号上 PPG 心率估计 | 60/72/90/120 bpm 四档，误差 ≤3 bpm | `tests/test_algorithms.py` 全绿 |
| 合成信号上 ECG QRS 检测 | 60/75/100 bpm，心率误差 ≤2 bpm，R 波灵敏度 ≥0.98 | 同上 |
| SpO2 方法链路 | 构造 R=0.5/0.6/0.8，恢复误差 ≤0.06 | 同上 |
| 串口协议 | 往返一致、CRC 错误可检出、半帧续传、噪声可重同步 | 同上 |
| **真实数据验证** | BIDMC 数据集上，用同段 ECG 作真值，PPG 心率 MAE ≤3 bpm（实测 5 例 77 窗口 MAE 0.64） | `tools/validate_bidmc.py` 输出 |
| **固件侧算法一致性** | C 实现与已验证的 Python 实现在同一批数据上偏差 ≤3 bpm（合成）/ ≤6 bpm（真实数据） | `tests/test_algo_conformance.py` |

## 三、诚实边界（写进简历前逐条检查）

1. P0 的结论只能表述为「**算法在合成信号与公开 ICU 数据集上验证通过**」，不能表述为「可穿戴实测」。
2. BIDMC 是 ICU 静息数据（多为卧床、心率范围集中、运动伪影少），**不能等同于可穿戴在运动场景下的表现**——这句话要主动说，比被追问更好。
3. SpO2 输出必须带「未标定」限定：方法链路可复现，但数值需要参考血氧仪标定后才可信。
4. 真机部分（P1–P3）完成前，简历里不写「采集链路」「低功耗实测」；完成并留下证据后再写，并注明实测条件。
5. 借用他人代码/思路的部分在 `docs/00-参考项目调研.md` 中标明来源与许可证。
