## 三、MAX30102 驱动主机端单测（模拟 I2C 芯片，无需硬件）

命令：`./.venv/bin/python tests/test_driver_host.py`

| 用例 | 覆盖的风险点 | 结果 |
|---|---|---|
| 初始化成功（PART_ID=0x15） | I2C 通不通、器件对不对 | 通过 |
| 写入 SpO2 模式与 LED 电流 | 配置寄存器位是否正确 | 通过（mode=0x03, led=0x33） |
| PART_ID 不匹配时拒绝初始化 | 误把 MAX30100/30105 当 30102 用 | 通过 |
| 非法 SR/PW 组合被拒绝 | 配置出「脉宽 > 采样周期」→ FIFO 永远溢出 | 通过 |
| FIFO 可用样本数（普通 / 指针回绕） | 5 位指针模 32 计算错误 | 通过（wr=2, rd=30 → 4） |
| 溢出后丢弃并清指针 | 溢出后新旧样本混读 | 通过（累计 overlaps=3，三指针清零） |
| FIFO 读取与 18 位解析 | 跨 3 字节拼接与 >16 位数据 | 通过（131071 / 262143 等边界值） |
| FIFO 空时返回 0 | 空读导致脏数据 | 通过 |
| 温度换算 25.25 °C | 小数位位置（TEMP_FRAC 高 4 位） | 通过（**此用例抓出并修掉了一个真实 bug**，见下） |

合计 **10 项，全部通过**。

### 单测抓到的真实 bug（值得写进调试记录）

- **现象**：读片内温度永远得到 `xx.00 °C`，小数部分恒为 0。
- **根因**：`TEMP_FRAC` 寄存器的小数部分在**高 4 位**（bit7:4），初版实现按低 4 位解析。
- **定位方式**：主机端单测里把 `TEMP_FRAC` 写成 `0x40`（期望 0.25 °C），实测输出 0 → 一次运行即定位。
- **修正**：`(frac >> 4) & 0x0F`。
- **意义**：这类 bug 在真机上要靠「一边加热探头一边读温度」才能发现，成本极高；解耦 + 模拟芯片把它变成毫秒级用例。

## 四、真实数据验证（PhysioNet BIDMC：同段 PPG 与 ECG 配对）

命令：

```bash
mkdir -p data/raw
curl -o data/raw/bidmc01.dat https://physionet.org/files/bidmc/1.0.0/bidmc01.dat
curl -o data/raw/bidmc01.hea https://physionet.org/files/bidmc/1.0.0/bidmc01.hea
./.venv/bin/python tools/validate_bidmc.py --records bidmc01,bidmc02 --quiet --out data/validation_bidmc.csv
```

方法：30 s 滑窗；**PPG 估心率** vs **同一段记录的 ECG 心率（真值）**。

| 记录 | 有效窗口 | MAE (bpm) | RMSE (bpm) | P95 (bpm) | 质量门限通过 |
|---|---:|---:|---:|---:|---:|
| bidmc01 | 16 | 0.21 | 0.48 | 1.10 | 16/16 |
| bidmc02 | 16 | 0.48 | 0.67 | 1.10 | 16/16 |
| **合计** | **32** | **0.34** | **0.58** | **1.10** | **32/32** |

> 数据量说明：BIDMC 共 53 例，本仓库当前已下载并验证 2 例（下载受 PhysioNet 带宽限制，脚本支持
> `--records` 传任意多条，后续会扩展到 10 例以上）。**不夸大样本量**：这里报的是「已跑过的记录」的实际数字。

### 边界（必须主动说明）
- BIDMC 是 **ICU 静息数据**：受试者多卧床、心率范围集中、运动伪影少。它验证的是「采集链路 + 峰值检测算法」的正确性，**不等价于可穿戴在运动场景下的表现**。
- 这段验证用的是**数据集里的 PPG**，不是本项目硬件采的 PPG。真机数据的验证属于 P1（待上机）。
